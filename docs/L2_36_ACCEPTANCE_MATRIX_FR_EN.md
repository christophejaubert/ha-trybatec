## Risques techniques identifiés / Technical risks

1. `queue_b15_plan(..., retry_pending=True)` re-enqueues all journal entries, including an entry that may already have been written but not yet marked verified after a partial batch failure. Treat this as a **potential duplication or inconsistent Recorder history** until source-specific confirmation. No claim of a production incident.
2. The new pure coverage proof derives its `measured` quantity from the existing **raw consumption variant**, not directly from index readings. It must be fed only by the trusted backend after source qualification. It **cannot** be accepted as a browser-supplied declaration.
3. Day boundaries created by `_bucket()` in `history.py` may place a qualified increment in an adjacent civil day. Deriving verified coverage bounds must preserve the existing date convention and avoid an untested change to `make_b15_plan`.
4. `history_recorder_b15.verify_b15_recorder` compares the planned hourly buckets with readback; a live failure/restart/delayed Recorder write remains an acceptance item. Never infer successful persistence from enqueue status.
5. A new evidence field must be bound to a complete source/decision fingerprint, and L3/#88 must check it against Recorder and physical inventory independently. No activation based on metadata alone.

## Qualification gates / Portes de qualification

- **G1 — Pure:** both new modules, 21 synthetic test cases locally passed, no Home Assistant imports, no writes.
- **G2 — Integration:** not done: reproduce exact current repository tree, attach strictly read-only adapters, test before/after/source provenance and rollback variants with existing test suite.
- **G3 — CI:** not done on new files. A new GitHub branch, PR and exact-head CI are subject to a separate **grouped GitHub publication authorization**.
- **G4 — HA isolated:** not done: staged Recorder V1→V2→V3, partial-batch recovery, read-after-write, forced crash/restart, version conflict, Energy preferences and idempotence.
- **G5 — HA real:** not done and **not authorized**: any Recorder write, real Energy switch, migration or restore.
